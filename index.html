Hullwork, the page you would open every day

The four you would actually open, plus the two behind projects — rendered by the same functions a running instance serves them with.

This is a snapshot, not a live instance. Nothing here is running, no error is being triaged, and the numbers do not change while you look at them.

The data is invented — acme/checkout-api does not exist — because a public demo should not carry another project's issue titles. The layout, the wording and every field are the real ones: these files come out of hullwork.page, not out of a design tool.

  • instance The daily read. What is running, what is stuck behind it, what is waiting on you — and, below the fold, what an evaluator wants: the credential split, the seal, the cost.
  • items Everything this instance knows about, with its lane and how long it has been where it is.
  • one item, with its evidence The interesting one: an attempt that reached a pull request, its six phases with exit codes, the red gate failing as it must, and the provenance seal naming the model that answered.
  • projects Two repositories on one instance, each with the manifest it was registered from.

There is nothing to log in to. On a real instance the URL carries a bearer token and that URL is the credential — mint one with hullwork page-token, and everything without it gets the same 404 an unknown path gets.
